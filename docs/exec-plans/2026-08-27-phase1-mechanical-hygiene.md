# Phase 1 — Mechanical hygiene

## Goal

Convert first-party text to UTF-8, resolve OneDrive conflict-copy files, stop
tracking build outputs, and start the third-party/asset license checklist —
with zero gameplay or C++ logic changes.

## In scope

- UTF-8 conversion of first-party `.cpp`/`.h` files (CP932 → UTF-8 with BOM).
- Deleting proven-dead `*-DESKTOP-2FSCGV3.*` conflict copies.
- `.gitignore` additions for compiled shader bytecode and future conflict copies.
- Starting `docs/portfolio/ASSET_LICENSE_CHECKLIST.md` with what is actually known.

## Out of scope

- HLSL shader encoding (see Result below — reverted, kept as a follow-up).
- Any ownership/lifetime/decomposition work (Phase 2+).
- Resolving the "unverified" rows of the asset license checklist (needs a human with provenance knowledge).

## Observed files/dependencies

- `docs/analysis/ENCODING_REPORT_before.txt`: 109 first-party files flagged CP932 (102 `.cpp`/`.h` + 7 `.hlsl`), 0 files with an undecodable/unknown encoding.
- `docs/analysis/DUPLICATE_REPORT.md`: 3 source conflict copies + 8 compiled-shader conflict copies, none referenced by the `.vcxproj`.
- `imgui/` and `assimp/` are vendored without their upstream `LICENSE` files.

## Behavior invariants

- No `.cpp`/`.h` text content change beyond byte-level re-encoding (verified character-for-character identical after decode).
- No gameplay constant, asset path, or shader constant changes.
- Deleted files must be (a) absent from `.vcxproj` membership in every configuration and (b) not referenced by literal filename anywhere in first-party source.

## Planned steps

1. Resolve conflict copies: check `.vcxproj` `ClCompile`/`ClInclude`/`FxCompile` membership for every `*-DESKTOP-2FSCGV3.*` file; delete only files proven unreferenced.
2. Convert the 102 flagged `.cpp`/`.h` files CP932 → UTF-8 with BOM; verify losslessness by decoding old (CP932) and new (UTF-8) bytes and comparing the resulting text for exact equality.
3. Attempt the same for the 7 `.hlsl` files; if the shader compiler rejects it, revert those specific files rather than force the conversion.
4. Rebuild `Debug|x64` from clean after each mechanical step; smoke-launch the exe.
5. Add `*.cso` and `*-DESKTOP-*` to `.gitignore`; stop tracking already-committed `.cso` files.
6. Populate `docs/portfolio/ASSET_LICENSE_CHECKLIST.md` with verifiable facts only (no guessed license status for unverified assets).

## Validation commands/checks

```
python scripts/check_text_encoding.py .        # before: 109 CP932; after: "all target text is UTF-8 compatible" (cpp/h only — see Result)
MSBuild.exe "GM31 23.04.18.vcxproj" /p:Configuration=Debug /p:Platform=x64 /t:Rebuild
```
Result each time: 0 errors. Executable smoke-launched with working directory = project root after both the conflict-copy cleanup and the encoding conversion; stayed alive 5s each time (terminated by the agent, not a crash).

Lossless-conversion check: for all 100 converted `.cpp`/`.h` files (2 of the original 109 were the deleted conflict copies), `git show HEAD~1:<file>` decoded as `cp932` was compared to the new file decoded as `utf-8-sig` — all 100 matched exactly, including the 7 `.hlsl` files before they were reverted.

## Risks and rollback

- Risk realized: converting `.hlsl` files to UTF-8-with-BOM broke the shader compiler (`fxc`): `error X3000: Illegal character in shader file` at the BOM. **Mitigation applied:** reverted those 7 files to CP932 via `git checkout --`; confirmed the full project still rebuilds with 0 errors. HLSL encoding conversion is deferred — a future task could try UTF-8 *without* BOM specifically for `.hlsl`, or leave it CP932 indefinitely since fxc output (compiled bytecode) is identical either way and only comments are affected.
- Rollback for any step: the `original-submission` tag and each theme's own commit make every change independently revertible.

## Result

- 100 `.cpp`/`.h` files converted CP932 → UTF-8(BOM), verified lossless, verified building and smoke-launching.
- 7 `.hlsl` files intentionally left as CP932 (see risk note above).
- 11 dead conflict-copy files deleted (3 source, 8 compiled shader), all confirmed unreferenced by the `.vcxproj` in any configuration and by no first-party source file.
- All 16 tracked `.cso` files un-tracked (kept on disk; regenerated by every build) and `.gitignore` updated so future builds don't re-add them.
- `docs/portfolio/ASSET_LICENSE_CHECKLIST.md` filled in for Assimp/Dear ImGui (both vendored without their license files — a real, actionable finding) and asset rows marked explicitly "unverified" rather than guessed.
